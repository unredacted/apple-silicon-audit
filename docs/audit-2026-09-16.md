# Codebase audit — 2026-09-16

The core architecture is coherent: kernel observations, inferred device identity, and Apple's
published claims are separate facts with explicit provenance. The fixture/live-reader boundary,
shared core for the CLI and apps, and data-driven inventory are worth keeping. The most consequential
problems were in error handling and in presenting incomplete evidence as a definite answer.

Reviewed kernel collection and decoding, identity and data loading, exports/imports, the CLI,
UI verdicts and report presentation, Watch transfer/storage, the schema and results generator,
build/release scripts, and platform icon assets. Changes preserve schema 1.x and the existing
platform deployment targets. Historical evidence and contributed measurements remain intact.

## Findings fixed

| Area | Finding and change |
| --- | --- |
| Fault-test timeout | Reading child stdout to EOF before starting the timeout could hang forever. The parent now drains a nonblocking pipe under a monotonic deadline, caps output at 64 KiB, kills and reaps a timed-out child, and reports failure. |
| Compact imports | Deflate output previously grew without a bound. Imports now cap encoded input and decompressed JSON, with a 512 KiB JSON ceiling matching the results database. |
| Import interpretation | Common decoding now rejects unsupported schema versions, invalid variants, and duplicate fact IDs across both arrays. A missing `variant` uses the schema's `full` default. This is typed application validation; full JSON Schema validation remains the results tooling's job. |
| Kernel discovery | Repeated/backwards OIDs and inconsistent subtree names no longer turn a partial walk into apparent success. Collected facts are retained with a failure reason. |
| Live compatibility | A live test required a 12-byte capability mask. This host returned 13 bytes. The test now requires coverage of the known bits; the decoder already preserves additional bits. The fixed 12-byte fixture checks remain. |
| Pointer self-test | Observed tags take precedence over negative kernel flags; missing keys cannot establish missing hardware. Zero successful allocations produce an error instead of a negative verdict. |
| Fault-test claims | SIGKILL is described as consistent with a tag-check failure, with the cause requiring crash-report confirmation. One surviving out-of-bounds store cannot establish disabled enforcement because adjacent allocations can share tags. CLI, UI, README, spec, and generated notes now say this. |
| Overview verdicts | An undecodable or negative tagging gauge is unknown, rather than silently becoming zero. An incomplete mitigation group cannot become a confident yes/no based only on its readable members. Legacy PAC keys fill an absent canonical key, matching the results matrix. |
| Results conflicts | Unrecognized values stored as `value_hex` and their byte lengths now participate in comparisons. Rejected submissions cannot contaminate accepted-result conflicts. Duplicate fact IDs are rejected. Failed validation cannot overwrite published artifacts. |
| Results CI | Inventory edits trigger regeneration. Generator regression tests run in CI. Push retries regenerate against the updated main branch instead of replaying stale generated files. |
| Export and refresh | UI export filenames use the existing sanitizer; overlapping audit refreshes are suppressed. |
| Watch transfers | Outgoing files use UUIDs instead of second-resolution timestamps, preventing same-second collisions. Completion removes the staged file. |
| Developer tooling | CLI rejects `--walk-refused` without `--fixture`; its summary counts flags consistently. Version bumps validate the build number before changing files. SwiftPM no longer warns about the intentionally source-read fixture. iOS joins the simulator UI CI checks. |
| Visual identity | Replaced the generic monochrome chip with a blue silicon-and-inspection mark. All 25 catalog image references, light/dark art, macOS tile sizes, TV shelves/layers, Vision layers, the README, and results site use the new identity. Regeneration is one script. |

## Remaining release qualification

Build success does not replace device testing. This pass did not repeat physical Watch-to-iPhone
background delivery, tvOS camera scanning, VoiceOver/Dynamic Type review, or signed enhanced-security
fault tests on the new OS. Existing evidence is retained, but those workflows should be repeated
before distribution. No App Store archive was signed, uploaded, or published.

The hardware/documentation data was checked structurally and through fixture/live behavior; this
was not a new source-by-source review of every chip mapping or Apple's entire security table.
New kernel bits remain visible as unnamed capabilities until their SDK definitions are deliberately
reviewed. Runtime imports are not a substitute for the results database's stricter schema/privacy
validation. The new artwork uses the existing asset-catalog pipeline; Icon Composer adoption can be
a separate visual enhancement if dynamic appearance variants are desired.
